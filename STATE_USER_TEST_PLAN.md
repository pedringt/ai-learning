# State outside-user test

Use this with 3–5 people who have not been coached on State. The public portfolio does not need to change while testing is underway.

## The 20-minute session

1. Give the participant the State prototype link and say only: “Northstar is an unfamiliar project. Use State to understand it well enough to brief a teammate.”
2. Ask them to find:
   - the current pilot direction;
   - the most consequential unresolved blocker;
   - one proposed change that still needs a human decision;
   - what State knows versus what remains uncertain about launch readiness.
3. Ask them to use Ask for a short briefing.
4. Do not explain the navigation unless they are fully stuck. Record the first place they hesitate.
5. End with three questions:
   - What did you trust, and why?
   - What felt confusing or slow?
   - What would make you use this instead of a maintained document?

## Record only these measures

| Measure | Result |
| --- | --- |
| Found the Project view without help | Yes / No |
| Correctly identified a blocker | Yes / No |
| Understood that Review had not changed Current State | Yes / No |
| Ask response time | Seconds |
| First hesitation | Short note |
| Most useful part | Short quote or paraphrase |
| Most confusing part | Short quote or paraphrase |

## Portfolio evidence threshold

Add a user-testing note to the portfolio only after at least three sessions. Report the sample honestly, describe the repeated behavior you observed, and name one concrete change made because of it. Do not present this as market validation or product adoption.

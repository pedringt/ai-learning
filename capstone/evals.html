Eval Suite — Sample Cases

Before the pilot launches, this is what "we tested it" actually has to mean — concrete cases run against the CONFIGURE flow, not a general claim that the agent "works." This is a working sample from the full 30–50 case suite the guide's Evaluate section calls for, built against the case types in that section's table (core how-to, access/ambiguity, billing, technical/failure, human-required safety).

Status: 12 sample cases below, one full CSV row format shown for each so the pattern is reusable. The full 30–50 case suite (this set expanded with more variants per category, run against a real trace) is the rest of VALIDATE, along with launch-readiness sign-off — not yet built.

Full CSV fields (per case): Case ID, Case Type, Input, Expected Behavior, Expected Source/Tool, Pass Criteria, Actual Result, Pass/Fail, Severity, Notes — same template as the downloadable Meridian Eval Template in the guide.

Why these 12: Picked to cover every case type from the guide's eval table at least twice, plus one case (E12) built directly from the Trace Autopsy incident — the whole point of a post-incident eval is that the failure becomes a permanent regression test, not just a one-time fix. E06 and E10 double as guardrail checks, not just quality checks, since a single failure there is the zero-tolerance trigger defined in PLAN.

Agent Flow — Meridian Tier 1 Support Pilot

One-page flow from ticket arrival to human handoff, built from the classify → retrieve → draft → confidence-check → escalate logic worked out in PLAN, plus the back-and-forth escalation rule.

Not shown as a separate branch: money/security categories (refunds, credits, disputes, password resets, account changes, security actions) skip drafting entirely per the PLAN Guardrails decision — they're folded into the "high-risk category" branch below, which routes straight to a human with no AI draft attempt.

Key decision points

  • Category check — money/security categories never get an AI draft, regardless of confidence. This is a hard rule, not a judgment call.
  • Confidence check — independent from category risk. A "safe" category can still get flagged with a reviewer note if the AI isn't confident (ambiguous request, conflicting KB sources, missing info).
  • Escalation check (multi-turn) — triggers on whichever comes first: 5+ exchanges (justified by the ~12% of tickets that naturally run long, per the simulated 90-day data pull — see open question 11 in the working tracker), signs of an upset/repeating customer, a high-risk category surfacing mid-conversation even if the ticket didn't start that way, or the customer explicitly asking for a supervisor/to escalate (added after rep discovery — the cleanest signal of the four, since it doesn't require inference).
  • Human review outcome — always one of approve / edit / start over, whether the ticket was drafted or fully human-written. Nothing sends to the customer without a human touching it first, per the pilot's human-boundary rule.

Data sources feeding this flow

  • Ticket content + category (help desk tool)
  • Knowledge base articles, via semantic/embedding-based retrieval rather than basic keyword matching — sidesteps the search limitation reps deal with today, though the underlying content problem (~20% unreviewed/stale articles — open question 2) still applies regardless of retrieval method
  • Conversation history (for the exchange count and mid-thread category check)
  • Confidence signal from the drafting step itself
  • Billing/account-status data — resolved simpler than expected: this already exists as a synced field on the ticket (nightly sync from the billing system), just not currently enabled for the Tier 1 view. No new integration or approval needed — enabling the existing field for Tier 1 (a standalone recommendation, not pilot-scoped) gives both reps and the agent access to the same already-approved data source. Caveat: up to 24 hrs stale due to the nightly sync.

Pending validation: real rep input (see Rep Discovery Questions in the working tracker) may confirm or adjust the workflow-model assumption this flow is built on (open question 4), and could refine the escalation logic further. The billing field (above) folds into the "retrieve relevant knowledge" step once enabled — no separate node needed. Pilot targets that depend on this flow (first-response time, quality) are locked in the PLAN deliverable.

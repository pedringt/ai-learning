Building State with AI

Project history is relatively easy to preserve. The harder problem is knowing what a team should actually treat as true right now, especially as new and possibly conflicting information keeps arriving. I built State to test that, and building it showed me how much control a product needs around AI interpretation.

The problem

Project history is easy to preserve. Knowing what to treat as true right now is harder.

As AI projects got longer, I kept carrying summaries from one chat to the next. I wanted to know whether maintaining a project summary would work better than reconstructing context from history.

I compared raw history, stronger reconstruction instructions, and a maintained summary. The maintained version helped, but a failure in that early prototype changed what I was actually trying to build, more on that below.

What changed for me

The problem was no longer just preserving context.

I realized I didn't want important project truth to depend on what an AI remembered or reconstructed at all.

I needed an external record that both people and AI could work from, while keeping accepted understanding, new evidence, unresolved information, and project history separate.

I kept going because I wanted to understand a harder question: what should AI be allowed to change, and what should stay under human control?

What I built

State maintains a current, trustworthy, human-approved understanding of a project as new information arrives.

The core loop is simple:

Something happens→Evidence→AI interprets→Human reviews→Current State updates

Questions, History, Ask, and Copy context all support that loop, without needing equal weight in a first explanation. Six parts keep it honest:

NotesWhat came in

Meeting notes, decisions, corrections, and approved Slack conversations are preserved as evidence.

Current StateWhat the team relies on now

A readable view presents what the project currently treats as true.

ReviewWhat may need to change

Recommendations wait for a human to accept or leave unchanged.

Open ItemsWhat still needs attention

Reviews, blockers, and open questions stay visible without being mistaken for facts.

HistoryHow the understanding changed

Accepted changes keep before, after, reason, decision, and source together.

AskHow the context gets used

Answers keep accepted facts, pending reviews, questions, and evidence distinct.

Only approved Slack channels are evaluated automatically into Evidence. Everything else in Notes is still entered by hand.

The product decisions

The hardest part wasn't building State. It was deciding what AI should be allowed to do inside it.

AI should not decide what is trueThe authority model

AI can propose that Current State should change. It cannot make that change happen. Only a person can accept a Review and move something into Current State. That's the central decision the whole product is built around.

AI interprets→software enforces→people decide
Valid AI output can still be wrongUnknown became 0%

Early on, the model turned an unresolved automation target into a confident 0%, an answer that fit the schema perfectly and was flatly wrong: it stated a decision the project had never made. That's why software checks references and versions before anything reaches Review, and why correctness gets judged against what the project actually knows, not just whether the output parses.

Not every AI failure is a model failureThe wrong billing contact

Ask once returned the wrong billing contact. It would have been easy to blame the model and rewrite the prompt. Looking closer, the model had reasoned fine, retrieval had handed it the wrong context to reason about. Fixing the routing fixed the answer. I try to find the actual failing layer before touching a prompt.

Don't ship an AI improvement just because it sounds betterStreaming, twice

Streaming the answer as it generated looked like an obvious win for perceived speed. The first version shipped with corrupted, token-split text in the visible answer, so I turned it off and kept the slower, validated response instead. Streaming only came back once I could stream the visible text safely while the structured answer underneath was still fully validated before it counted as real.

How it evolved

The shape kept changing once I actually used it.

Current StateWent from a database view of separate facts to something closer to a brief someone would actually read to learn about the project.
ReviewsBecame the center of the product. Accepting one now shows exactly what's about to change and asks for confirmation before anything consequential happens.
QuestionsBecame an explicit way to keep an unresolved unknown open instead of letting it quietly slip into an answer.
AskStayed strictly read-only. If someone asks it to change something, it redirects them to add evidence instead of quietly acting on the request.
Copy contextLet the maintained Current State travel into Claude or ChatGPT, instead of staying locked inside State.
Where I landed

State is most useful when a team needs more than a plausible summary.

State is not necessary for every project. A maintained Claude Artifact or similar document is probably easier and good enough for lightweight solo work. State becomes more useful as information changes frequently, multiple people or sources are involved, old and new information can conflict, decisions carry real consequences, and someone needs actual control over what counts as authoritative rather than whatever was said most recently.

My biggest takeaway was that AI interpretation and product authority need to be separate, and uncertainty needs to remain visible instead of quietly becoming a plausible-sounding answer. State doesn't replace Claude or ChatGPT: it maintains the project context that can be carried into those tools, while keeping accepted understanding separate from whatever an AI generates in the moment.

How I worked with AI
My role

Product concept, requirements, UX direction, evaluation, acceptance criteria, tradeoffs, hands-on use, and final decisions.

AI’s role

Technical approaches, much of the frontend/backend implementation, model integration, debugging, log analysis, and automated QA.

I used ChatGPT and Claude Code as collaborators throughout the build, getting more deliberate about handing off work without losing important decisions or constraints.

Move quickly while learning the product, then deliberately shift into a maintainable build mode.

failure into permanent coverage. The danger is not AI speed itself - it is letting fast changes

outrun architecture, ownership, and tests.

AI-specific build rules

✓Models make semantic judgments; software should own mechanical facts

when possible.

✓Capability does not imply authority: recommend, validate, authorize, then

mutate.

✓Adapt provider output to the product contract, not the reverse.

✓Use real product usage to discover useful rework.

✓Schema-valid is not the same as semantically correct.

✓Repeated implementation debt means the process or ownership model needs

to change.

Move fast while discovering the product. Then make implementation boring: one source of truth, bounded AI jobs, explicit phase gates,

permanent regression coverage, and deployed-browser verification.

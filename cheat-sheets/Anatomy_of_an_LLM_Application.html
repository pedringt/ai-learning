05 / list

Design for mistakes

  • Preserve source evidence unchanged
  • Keep source separate from interpretation
  • Schema-valid does not prove semantic truth
  • Use software for mechanical facts
  • Show provenance and reversible history
  • Fail safely when the model is unavailable
REFERENCE DETAIL / RESTORED

Authority and interpretation are different

What a model response does not prove

OutputWhat remains to verify
Schema-valid JSONFields, values and references have permitted meanings; downstream logic is still correct
Well-grounded proposalIt is not necessarily accepted Current State
A newer source existsIt may qualify prior truth without itself being reviewed or approved
The model explains a changeThe application still checks authorization, permitted transitions and durable persistence
Current State vs repeated reconstruction: For normal questions about current facts, use the maintained authoritative Current State rather than asking the model to infer truth from raw historical evidence every time. Keep source evidence immutable and distinguish it from interpretation, pending proposals and accepted state.
Possible stale state: If an unresolved Review could make maintained state stale, present the established fact with a visible qualification. Never silently promote the proposal to accepted truth. The model interprets; software enforces; people authorize consequential transitions.

Match architecture to the job: rules, prompts, retrieval, tools, workflows, agents and fine-tuning.

02 / cards

Common false choices

RAG vs fine-tuning

Retrieve changing or private facts; tune when many task examples support improving behavior.

Workflow vs agent

Choose fixed sequences for known routes; agent only when variable planning earns the cost.

Architecture questions

  • Where does authoritative state live?
  • What can the model actually change?
REFERENCE DETAIL / RESTORED

Evaluate the layer that carries the risk

Evaluation map

LayerWhat to verify
RetrievalRelevant source found, freshness, permission filtering, ranking and provenance
Model outputGroundedness, completeness, uncertainty handling, structured fields and safety
Tools/actionsCorrect tool, valid arguments, approval, scopes and side-effect recovery
End-to-end workflowTask outcome, latency, cost, human review effort and fallback behavior
Specific design progression: For a policy Q&A assistant, start with retrieval against permission-filtered current policies. To update a customer account, add a narrowly scoped action tool, server-side validation and explicit authorization. Use an agent only if investigative paths genuinely vary enough to justify the additional autonomy.
Architecture boundary: Retrieval solves changing/private facts; fine-tuning can adapt repeated task behavior but not update authoritative knowledge. A fixed workflow is easier to audit than an agent when the sequence is known. Access controls and irreversible approvals must never rely on a prompt alone.

AI CUSTOMER SUCCESS / FIELD GUIDE

A practical guide for turning vague customer complaints into reproducible evidence, likely cause, impact, and a verified outcome.

Core mindset: Debug the whole system, not just Claude. Find the first point where actual

behavior stopped matching expected behavior, collect clear evidence, and help the right owner

act.

What is debugging?

What is a trace?

Your value

A step-by-step record of one request: inputs, model calls, tool calls,

outputs, errors, timing, and usage.

Turn a vague complaint into evidence another team can reproduce,

prioritize, and fix without re-interviewing the customer.

Trace Reading Workflow

Read left to right. Stop at the first input, decision, tool result, or interpretation that diverges from expectation.

Step-by-step debugging

Clarify expected behavior. One plain sentence: Given X, the agent should do Y. Confirm source-of-truth policy.

Capture actual behavior. Exact request, response, timestamps, conversation/request ID, account conditions.

Assess urgency and safety. Escalate privacy exposure, unauthorized actions, financial harm, security risk, or broad impact immediately.

Find the trace. Search by conversation/request ID, account, time, environment, or trace ID.

Read from left to right. User input → context/retrieval → model → tool calls → tool results → final output.

Classify likely cause. Instruction, context, retrieval, tool, permissions, model wording, workflow, or operations.

Reproduce safely. Start with the exact request in a test/approved environment; change one condition at a time.

Compare. Pair the failing trace with a similar good trace when possible.

Route smallest fix. CS may improve examples/tests; engineering changes code/tools; security changes policy; PM owns product tradeoffs.

Regression + close loop. Original, paraphrases, neighbors, permissions/failures, customer update, monitoring plan.

Good descriptions reduce ambiguity

Vague

Clearer

check_order

Retrieve latest order/shipping status for a verified order ID. Status questions only; do not modify order.

refund

Create a refund only after eligibility and user authorization are confirmed. Requires order ID, amount, reason, approval token.

Find a customer using verified email/account ID. Return possible matches; do not expose records without authorization.

Safe reproduction rule: never repeat a risky action on a real customer account just to prove it

MCP in simple terms

MCP (Model Context Protocol) is a standard way for an AI application to connect to outside

tools and information - like a common plug between the AI host and systems that expose

capabilities.

MCP host

CRM / DB / docs

MCP is not Claude, and it is not the CRM/database. It is the communication standard

connecting an AI application to the server exposing those capabilities.

Beginner capability checklist

✓Explain agent, trace, log, metric, and eval.

✓Create a compact regression eval set.

✓Find a trace from a conversation/request ID.

✓Recognize privacy/security/financial escalation triggers.

✓Narrate input → tools/context → output.

✓Check latency, retries, usage/cost, reliability.

✓Identify the first divergence.

✓Explain MCP host/client/server/system.

✓Separate model failure from upstream data/tool failure.

✓Route the fix to the correct owner.

✓Reproduce safely, one variable at a time.

✓Validate the fix and close the customer loop.

Your job is not to know every implementation detail. It is to make the failure understandable: what should have happened, what actually

happened, where the first divergence appeared, how severe it is, and what evidence shows the fix worked.

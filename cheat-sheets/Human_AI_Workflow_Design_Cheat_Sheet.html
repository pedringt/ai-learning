Human–AI Workflow Design

Make judgment, authority, uncertainty, and recovery explicit.

Suggest vs enforce vs authorize

AI suggestsSoftware enforcesPeople authorize

04 / list

Make uncertainty visible

  • Evidence is not automatically accepted truth
  • Pending is not approved; unknown is not zero
  • Show source freshness and provenance
  • Offer correction, rejection, unchanged, and escalation paths
05 / table

Failure recovery

FailureSafe response
Provider unavailableFail closed or use a deliberately limited fallback
Tool timeoutRetry only if safe; show manual path
Missing permissionDeny action and explain authorization
Weak evidenceRequest more or keep question open
Stale stateVersion check and re-review
Bad consequential actionPreserve history, reverse or escalate, add regression
06 / note

Remember

Human-in-the-loop is not a person tacked on at the end. Authority and recovery must be designed throughout the workflow.

PM design and release checklist

WhenCheck
Before designMap human authority, sensitive data, uncertainty, read/write scope and reversibility
Before releaseSeparate evidence from proposals, enforce validation/version checks, test approval and corrections, expose failures and fallback
During iterationRetest original and neighboring cases, holdouts and repeat runs; measure silent misses, false certainty and human review burden
Recovery cases: When data is weak, keep a question open. When state is stale, block changes and require re-review. When tools fail, retry only if safe or escalate. When an unauthorized action slips through, preserve history, support reversal and add a regression case.
PRACTICAL FRAMEWORK / AI PRODUCT WORK

Reversible autonomy: decide, act, revoke

Is the action consequential or hard to reverse?Yes → approve firstNo → bound scope and verify recoveryMonitor defined evidenceReverse or compensate when contradictedRevoke autonomy when reliability degrades
GatePM question
Before actionIs the action low impact, reversible in practice, time-bounded, logged and within an approved permission scope?
After actionWhat contrary evidence, timeout or changed state triggers compensation or human review?
Authority withdrawalWhat failure rate, serious incident or missing evidence forces the system back to recommend-only?

Compensation is not deletion: retain the audit trail, and never call an action reversible without testing the recovery path.

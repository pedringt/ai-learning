Enterprise Data Readiness for AI

Before picking a model, verify that the information and access paths can support the job.

The readiness layers

  • Availability: Are the required sources present and accessible? Which records are missing?
  • Quality: Are values accurate, consistently formatted, deduplicated, and complete enough?
  • Meaning: Are key terms such as “active customer” defined the same way across systems?
  • Freshness: How quickly do updates propagate? Can users see timestamps and source provenance?
  • Permissions: Does the system preserve source-level user access? What is sensitive, logged, retained, or exported?
  • Integration: Which APIs, exports, connectors, owners, and failure modes exist?

Source-of-truth questions

  • Which system owns a fact? What happens when sources conflict?
  • Are IDs stable enough to join records? Are deleted or revoked items removed from indexes?
  • Can data be traced from answer back to the exact source and version?

Common failure patterns

  • Stale retrieval: a good-sounding answer uses last month's policy.
  • Permission leakage: an index exposes a confidential document to an unauthorized user.
  • Ambiguous join: customer IDs or units differ across systems, yielding misleading analysis.
  • Silent sync failure: the retrieval system appears healthy but stopped ingesting updates.

Worked example

  • An assistant must answer questions across CRM, internal docs, and support tickets. First map which source owns each answer, test contradictory records, identify user permission scopes, check update schedules, and validate citations.
  • Only then choose retrieval and model approaches. A more capable model cannot fix unreliable source ownership.

Questions to remember

  • Could a normal employee independently answer this with the available data?
  • Who may see the underlying record? What happens when a source changes or disappears?
  • Is this a data problem, retrieval problem, or generation problem?
